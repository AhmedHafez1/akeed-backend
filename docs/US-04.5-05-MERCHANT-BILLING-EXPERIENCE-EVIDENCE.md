# US-04.5-05 implementation evidence

Date: 2026-09-10

## Delivered

- A design-first Standalone billing experience at `/[locale]/billing` and a canonical Paymob return view at `/[locale]/billing/return`. Both redirect embedded Shopify visits back to Shopify settings.
- A typed `features/billing` API, provider and coordinator. Checkout submits only quantity and one stable `Idempotency-Key`; trusted server terms replace the preview before Paymob continuation. A deliberate “Start new purchase” action is the only way to rotate the key.
- Account, grant, low/zero/debt, pending approval, suspended, not-provisioned, disabled and viewer states in matching English/LTR and Arabic/RTL presentation.
- Opaque-cursor purchase and ledger append behavior, trusted localized money/dates, safe actor/reason labels, signed quantities, dispute/refund/reconciliation badges and responsive mobile cards.
- A bounded return reader that accepts only `purchaseRef`, reads immediately, polls no more than five additional times at two-second intervals, stops on terminal or reconciliation-required state, and turns timeout into manual refresh without creating another purchase.
- Dynamic Standalone navigation, a credit-page replacement for obsolete Standalone monthly-plan settings, and persistent billing recovery links on Standalone manual-order, test-send and retry credit denials. Embedded Shopify navigation and plan billing remain unchanged.
- Merchant API refinements: `billingEnabled`, purchase `updatedAt` and `reconciliationRequired`, and ledger `reasonCode` / `actorType` in place of raw staff reasons and actor IDs. All reads stay tenant-scoped and `private, no-store`.
- Paymob receives the configured return URL with only the tenant-scoped `purchaseRef` added by Akeed. No provider ID, organization ID, checkout secret, event hash, staff reason or reconciliation code is exposed.

No database migration was required.
