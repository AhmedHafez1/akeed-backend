## User story and value

As a non-technical merchant working in Arabic or English, on desktop or phone, I want a short guided flow that tells me exactly which orders are ready and why others aren't, so that I can import with confidence and fix problems without contacting support.

**Business value:** The file pipeline becomes a self-serve feature, and the "Nothing has been sent yet" message builds trust at every step.

## Scope

- The routes `/[locale]/imports/new` and `/[locale]/imports/[batchId]`, where the batch page renders the step matching the batch status.
- A three-step rail: Upload → Map → Review.
- Template download.
- File-level error states.
- The mapping form with import options and payment-value classification.
- The review summary, tabs, table, per-row include and error-report download.
- Draft resume and discard.
- Localization, RTL, dark mode, keyboard and mobile.

**Out of scope:** The commit and awaiting-start screens (US-04.6-06), the start dialog (US-04.6-07), history (US-04.6-08) and inline cell editing.

## Acceptance criteria

1. **Upload:**
   - A dropzone plus a "Choose file" button (`accept=".csv,.xlsx"`, keyboard operable, one file).
   - A client pre-check on extension and size (5 MB) with instant localized errors. The server remains authoritative.
   - While uploading: file name, size, a determinate progress bar (XHR upload progress), then "Reading your orders…".
   - Template links: CSV and Excel, in the current locale.
   - An "Open drafts" list, shown when drafts exist, with Resume/Discard.
2. **File-level errors** map every batch error code from the epic contract to a localized title, an explanation and one corrective action. Examples:
   - `IMPORT_FILE_PROTECTED`: "Remove the password in Excel and upload again."
   - `IMPORT_FILE_TYPE_UNSUPPORTED` for `.xls`: "Save as Excel Workbook (.xlsx) or CSV UTF-8."
   - `IMPORT_ROW_LIMIT_EXCEEDED`: "Split the file into parts of up to 5,000 orders."
   - `IMPORT_TOO_MANY_DRAFTS`: a list of the drafts to resume or discard.

   Unknown codes fall back to a generic message with a copyable batch or request ID.
3. **Duplicate file:** when `duplicateFileOf` is present, a warning banner reads "You uploaded this same file {time} ago", with actions "View earlier import" and "Continue anyway". Continuing is allowed.
4. **Map:**
   - One row per canonical field (required first), each with a select listing the file's headers, 2 sample values from the chosen column, and a confidence indicator: ✓ detected / ↺ from saved mapping / ⚠ needs attention / — not provided.
   - Required fields without a column block Continue, with inline errors.
   - An "Import settings" panel: phone country (default and flag), default currency and date format. Date format is shown only when the server reports ambiguity.
   - A "Payment values" panel, shown only when payment is mapped: each distinct value with its count and a COD / Not COD toggle. Unknown values must be chosen.
   - "Columns that won't be imported" is listed collapsed.
   - Saving calls `PUT /mapping` and moves to Review.
5. **Review:**
   - Summary tiles: Ready (success), Need fixing (destructive), Duplicates skipped (neutral), Excluded (warning), each with a count and one-line meaning.
   - Tabs filter the table by outcome.
   - Columns: row number, customer, phone (E.164, `dir="ltr"`), amount and currency (locale-formatted), order reference/date, and status with reasons (all issues, localized).
   - Pages of 50 via the rows cursor.
6. **Review banners:**
   - Date range "Orders from {min} to {max}", or "No order date column. Only import recent orders you intend to confirm."
   - "{n} orders are older than 7 days and won't be imported", when present.
   - "Nothing has been sent to customers", always.
7. **Possible duplicates:** each has an "Include anyway" checkbox showing the matched order ("Same phone and amount as #1042 on 16 Sep"). Toggling calls `PATCH` optimistically and rolls back on error; tiles update.
8. **Error report:** "Download rows to fix ({n})" downloads `errors.csv` (US-04.6-08 contract) with the copy "Fix these rows in your file and upload it again. Orders already imported will be skipped automatically."
9. The primary action "Import {ready} orders" is disabled at 0 with "No orders are ready to import". The secondary action is "Back to mapping". "Discard import" asks for confirmation.
10. **Resume and refresh:**
    - Refreshing or opening `/imports/{batchId}` at any time renders the right step from the server's status.
    - An expired draft shows "This import expired after 24 hours. Upload the file again."
    - Another org's or an unknown batch shows the not-found state.
11. **Access and accessibility:**
    - Viewers see the page read-only: no upload or mutation controls, and a "Only owners and admins can import orders" note.
    - Shopify embedded mode never shows the entry point, and the route redirects to the dashboard.
    - All text is from `orderImport.*` in `ar.json` and `en.json`.
    - The layout uses logical properties only, and phones and amounts are isolated with `dir="ltr"`/`<bdi>`.
    - Focus moves to the step heading on step change, tiles and tabs are keyboard reachable, and status is conveyed by text and icon, not color alone.
12. **Mobile (below 768 px):** the stepper collapses to "Step 2 of 3", the mapping becomes a stacked list, the review table becomes row cards, and the primary action is sticky at the bottom.

## Implementation notes

- **Backend:** None beyond the contracts in US-04.6-02 to 04.
- **Frontend:**
  - `features/order-imports/{api,domain,ui,skins/standalone}` following the feature pattern.
  - Queries: `queryKeys.orderImports.{list,detail,rows}`.
  - Upload via `XMLHttpRequest` for progress, or `fetchWithAuth` with a `FormData` body and no forced `Content-Type`.
  - Reuse `OnboardingStepRail`/`OnboardingStepProgress` (extract to `shared/ui/stepper` if they are onboarding-coupled), plus `Table`, `Pagination`, `Badge`, `Dialog`, `SegmentedControl` and `notify`.
  - Poll detail only while `status` is transitional.
  - Promote `manualOrderCurrencies` and `MANUAL_ORDER_PAYMENT_METHOD` from `features/orders/domain/manualOrder.model.ts` to `src/shared/commerce/orderCommerce.ts`, and re-import them in the manual form. The currency select in Import settings uses that list.
  - Reuse `ApiError`/`getErrorMessage` from `shared/lib/http.ts`, the shared `Badge` and `VerificationStatusBadge` tones, and the phone input's country list for the country picker: export `ALLOWED_COUNTRIES` (and its exclusion list) from `shared/ui/international-phone-input.tsx` rather than building a second list.
  - Follow the `frontend-dev` skill: tokens only, no raw palette classes.
- **Data:** No client storage of row data beyond the React Query cache.
- **Operations:** Client analytics events for the step funnel (no PII).
