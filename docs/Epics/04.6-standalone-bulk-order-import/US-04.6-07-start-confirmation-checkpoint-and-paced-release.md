## User story and value

As a merchant, I want to see exactly how many customers will be messaged, what it will cost and how long it will take before I start, and to be able to stop it, so that I stay in control of my customers' experience and my credits.

**Business value:** This protects the shared WhatsApp sender's quality rating through pacing, quiet hours and consent attestation. It avoids billing surprises and support tickets through the credit gate and cost preview, and gives Akeed a policy record through the stored attestation.

## Scope

- The start quote.
- The attestation.
- Start gates.
- The per-organization paced release scheduler.
- Quiet-hours pause.
- Auto-pause and resume.
- Stop remaining.
- 72-hour expiry.
- The start dialog and the releasing UI.

**Out of scope:** Changing templates, per-batch follow-up settings, scheduling a start for a future time, and partial starts.

## Acceptance criteria

1. `GET /api/order-imports/:id/start-quote` (owner/admin, batch `awaiting_start` or `paused`) returns:
   - `orders` (held count, N)
   - `accountingMode`
   - `creditsAvailable` or `slotsRemaining`
   - `estimatedCreditsMin = N`
   - `estimatedCreditsMax = N × (1 + followUpEnabled)`
   - `ratePerMinute`
   - `estimatedDurationMinutes`, including known quiet-hours gaps in the store timezone
   - `quietHours`
   - `startDeadlineAt`
   - `blockers[]`
   - `quoteToken`, an HMAC of the batch ID, N and the balance snapshot, valid for 10 minutes
2. The blockers, each with a code and a localized action, are:
   - `IMPORT_AUTO_VERIFY_DISABLED`, linking to Settings.
   - `INSUFFICIENT_CREDITS` when `creditsAvailable < N`, with `shortfall = N − available` and a Buy credits link prefilled with `max(100, roundUp50(shortfall))`.
   - `CREDIT_DEBT_OUTSTANDING`, `CREDIT_ACCOUNT_SUSPENDED` and `CREDIT_ACCOUNT_NOT_PROVISIONED`.
   - `IMPORT_PLAN_LIMIT_REACHED` when periodic-mode `slotsRemaining < N`.
   - `IMPORT_SETUP_INCOMPLETE` and `IMPORT_START_WINDOW_EXPIRED`.
3. `POST /api/order-imports/:id/start` requires `Idempotency-Key` and `{attestationVersion, quoteToken}`.
   - It fails with `IMPORT_ATTESTATION_REQUIRED` if the attestation is missing or not the current version, and with `IMPORT_QUOTE_STALE` (returning a fresh quote) if the token has expired or N or the balance changed so that a gate would now fail.
   - It re-evaluates every blocker server-side, then atomically sets `status = releasing`, `attested_by`, `attested_at`, `attestation_version`, `started_at` and `start_idempotency_key`, and enqueues the org's release scheduler.
   - The same key returns the same result; a second start with a different key returns `IMPORT_BATCH_STATE_CONFLICT`.
4. **Attestation text** (versioned `bulk-import-consent-v1`, AR/EN, stored by version): "I confirm these customers placed these cash-on-delivery orders with my store recently and expect to be contacted on WhatsApp about them."
5. **Release scheduler:**
   - A repeatable per-org BullMQ job `import.release` (job ID `import-release-<orgId>`) ticks every 30 s.
   - Each tick releases at most `ceil(rate × 0.5)` held events across that org's releasing batches, oldest `started_at` first, then row number.
   - It calls `releaseHeld(ids, NOW())` and then `dispatchById` for each released ID. A failed dispatch is left for the existing reconciler, because the event is now `released` with `dispatch_required = true`.
   - The rate comes from env `BULK_IMPORT_RELEASE_PER_MINUTE` (default 20, bounds 1–120).
6. **Quiet hours:** if the store is in quiet hours (`adjustForQuietHours` with the store's timezone and window, re-read every tick), the tick releases nothing, and the batch shows `quietHoursUntil`. Downstream quiet-hours and `sendDelayMinutes` logic is unchanged.
7. **Auto-pause:**
   - Each tick re-checks the same gates as the quote, except the quote token. If any gate fails, all the org's releasing batches become `paused` with `paused_reason` set to the blocker code, and nothing more is released.
   - An order released just before a balance drop that then fails with `INSUFFICIENT_CREDITS` follows the normal manual-order retry path and also triggers the pause.
   - `POST /:id/resume` re-runs the quote gates, requires no new attestation, and returns the batch to `releasing`.
8. **Stop remaining:**
   - `POST /:id/stop` (owner/admin, `releasing` or `paused`, idempotent) calls `withdrawHeld(batchId)`, sets `status = stopped`, and returns the counts released and withdrawn.
   - A stop racing a tick leaves each event either released or withdrawn (US-04.6-01 guarded updates).
   - Released orders continue normally; the UI says so.
9. **Completion and expiry:**
   - When a releasing batch has no held events left, it becomes `completed` with `completed_at`.
   - An hourly `import.expire` job withdraws holds of `awaiting_start` or `paused` batches past `start_deadline_at` and marks them `not_started`.
   - The scheduler removes its repeatable job when the org has no releasing batches.
10. Manual orders and Shopify orders never pass through the release scheduler, and their latency is unaffected by an import in progress.
11. **Start dialog (UI):** it opens from the imported screen or batch detail.
    - Shows the recipient count, the estimated duration with a quiet-hours note, the credit estimate ("970 credits now, up to 1,940 if customers need a follow-up"), the current balance and balance after the minimum, and the attestation checkbox.
    - "Start sending to 970 customers" is enabled only when there are no blockers and the checkbox is ticked.
    - A shortfall variant replaces the button with "Buy {n} credits" and explains that nothing starts until the balance covers all orders.
    - After buying credits, returning re-quotes automatically.
12. **Releasing view:**
    - A progress bar (released ÷ total), live counts (queued, sent, confirmed, canceled, no reply, failed from the verification lifecycle), rate text ("About 20 messages per minute"), and a quiet-hours or paused banner with the reason and a resolve action.
    - "Stop remaining" opens a confirmation dialog: "{n} customers haven't been contacted and won't be. Orders already sent continue normally."

## Edge cases

- The credit balance changes between quote and start (`IMPORT_QUOTE_STALE`) or during release (auto-pause).
- Credits are bought mid-pause (Resume works; auto-resume is not in the MVP).
- Two batches releasing share one org rate budget.
- The store timezone or quiet hours change mid-release, and the window crosses midnight.
- The flag is turned off mid-release (in-flight batches continue; start and resume are blocked).
- Auto-verify is toggled off and on (pause, then resume).
- Stop is clicked twice.
- Stop races the last tick.
- The start deadline passes while paused.
- The merchant's session member is removed after start (the batch continues).
- A Meta template is paused (existing verification failure path; batch counts reflect failures).
- The worker restarts (the repeatable job is re-registered on boot for orgs with releasing batches).

## Implementation notes

- **Backend:**
  - `order-import-release.processor.ts` on the `order-import` queue.
  - Gate evaluation is extracted into one `StandaloneSendReadinessService.evaluate(source, {required})` returning typed blockers. It absorbs:
    - the entitlement, auto-verify, credit and slot gates of `OrdersService.createManualOrder`;
    - the private `assertCreditEligible`;
    - the private `retryReadinessReason`.
  - `createManualOrder`, `retryOrderVerification` and the import quote, start, resume and release tick all call it, with **no** remaining direct calls to `CreditEligibilityService`/`hasAvailableSlot` from `orders.service.ts` or `order-imports`.
  - The manual path keeps its exact codes and bodies through a code map. This is proven by the manual-order and credit-usage contract suites passing unchanged.
  - The quote token is an HMAC with a server secret.
  - Duration estimate: `ceil(N / rate)` plus the minutes of quiet-hours windows overlapping that span.
- **Frontend:**
  - `StartConfirmationDialog`, and a releasing panel polling every 5 s.
  - The Buy credits link reuses the billing purchase flow with a `returnTo=/imports/{id}` param.
  - Emit a domain event on start and stop to refresh verification and billing queries.
  - Credit and billing blocker messages reuse the existing `creditErrors.*` translations and the manual-order `billingLink` feedback pattern; no parallel strings.
  - Buy credits reuses the existing billing purchase entry, not a new checkout.
- **Data:** Attestation fields on the batch are immutable once set.
- **Operations:** Metrics for released per tick, pause reasons and release lag.
  - Alert if a releasing batch has not released for 10 minutes outside quiet hours without a pause reason.
