## User story and value

As a merchant with my own spreadsheet layout, possibly with Arabic headers, I want Akeed to recognize my columns and remember my choices, so that each weekly import takes one click instead of a mapping exercise.

**Business value:** Merchants don't need to learn the template, and repeat imports get faster, which increases usage.

## Scope

- Alias-based auto-detection with confidence levels.
- The mapping contract and its validation.
- Import options: country, default currency, date format and payment-value classification.
- Saved profiles keyed by header signature.
- Re-validation trigger.

**Out of scope:** Row validation rules (US-04.6-04), AI/fuzzy matching beyond the normalized alias dictionary, and multi-sheet selection.

## Acceptance criteria

1. On upload, every canonical field gets a suggested source column and a confidence:
   - `exact`: normalized header equals an alias.
   - `partial`: the normalized header contains an alias token of 3 or more characters, with exactly one candidate.
   - `none`.

   Header normalization lowercases, strips Arabic diacritics and tatweel, unifies `أ/إ/آ→ا`, `ة→ه` and `ى→ي`, converts Arabic-Indic digits, and removes punctuation and whitespace.
2. The alias dictionary covers at least the following (EN/AR), versioned in code:
   - **Phone:** `phone`, `mobile`, `phone number`, `mobile number`, `whatsapp`, `tel`, `رقم الهاتف`, `الموبايل`, `رقم الموبايل`, `موبايل`, `تليفون`, `واتساب`, `رقم العميل`.
   - **Name:** `name`, `customer`, `customer name`, `client name`, `full name`, `billing name`, `shipping name`, `اسم العميل`, `الاسم`, `العميل`, `اسم المستلم`.
   - **First/last name:** `first name` / `last name`, `الاسم الاول` / `الاسم الاخير`.
   - **Amount:** `amount`, `total`, `order total`, `grand total`, `price`, `cod amount`, `collect amount`, `الاجمالي`, `المبلغ`, `السعر`, `قيمه الطلب`, `مبلغ التحصيل`.
   - **Order reference:** `order id`, `order number`, `order no`, `order #`, `name` (Shopify style `#1001`), `reference`, `رقم الطلب`, `كود الطلب`, `رقم الاوردر`.
   - **Currency:** `currency`, `العمله`.
   - **Payment method:** `payment method`, `payment`, `payment gateway`, `financial status`, `طريقه الدفع`, `الدفع`.
   - **Order date:** `date`, `order date`, `created at`, `created`, `التاريخ`, `تاريخ الطلب`.
   - **City, address and notes:** `city`, `governorate`, `المدينه`, `المحافظه`, `address`, `shipping address`, `العنوان`, `notes`, `note`, `ملاحظات`.
3. `name` is ambiguous between the order reference (Shopify exports) and the customer name. When a column matches both, it is assigned to the customer name only if no other customer-name candidate exists and its sample values are not mostly `#`-prefixed or numeric. Otherwise it is assigned to the order reference.
4. Mapping rules:
   - A field maps to at most one column, except customer name, which may map to first and last name columns (joined with a space).
   - A column maps to at most one field; a violation returns `IMPORT_MAPPING_INCOMPLETE` with `fieldErrors`.
   - Phone, name and amount are required.
   - Unmapped columns are ignored and listed as "not imported".
5. Import options, stored on the batch:
   - `country`: ISO-2, default is the store's `countryCode`, else `EG`.
   - `defaultCurrency`: default is the store's `shippingCurrency`, must be in `ONBOARDING_SHIPPING_CURRENCIES`.
   - `dateFormat`: `auto` | `DMY` | `MDY` | `YMD`. It is required only when the mapped date column contains values valid in both DMY and MDY and no value disambiguates them.
   - `paymentValueMap`: `{normalizedValue: 'cod' | 'not_cod'}` for each distinct payment value (up to 50 distinct values; beyond that, auto-classification applies without per-value override).
6. When a payment column is mapped, the response lists its distinct values with counts and an auto-classification. Values matching `isCashOnDeliveryPaymentSignal`, or the import dictionary (`cash`, `كاش`, `نقدي`, `عند الاستلام`, `collect`), are `cod`. Values matching `paid`, `مدفوع`, `visa`, `card`, `instapay`, `wallet`, `vodafone cash`, `fawry` or `prepaid` are `not_cod`. Anything else is `unknown`, and the merchant must choose before continuing.
7. `PUT /api/order-imports/:id/mapping` (draft only) validates, persists mapping and options, re-runs US-04.6-04 validation over the stored rows, and returns updated counts. It is idempotent for the same body. On a non-draft batch it returns `IMPORT_BATCH_STATE_CONFLICT`, and on an expired draft `IMPORT_BATCH_EXPIRED`.
8. Saving a mapping upserts `order_import_mapping_profiles` for `(org, header_signature)`, where the signature is the SHA-256 of the sorted, normalized headers. On the next upload with the same signature, the saved mapping and options are applied automatically and marked `source: 'saved'`, and the merchant can still change them. A saved mapping that references a header no longer present is ignored field by field and falls back to auto-detection.

## Edge cases

- Headers in mixed Arabic and English; a header of only `#`; two columns both named `Phone` (suffixed `Phone (2)`, and only the first is suggested).
- A phone column split as `Country code` + `Number` (not supported in the MVP: map `Number` and set the country).
- A Shopify export with `Name` as `#1001`, `Billing Name` and `Phone`/`Billing Phone`/`Shipping Phone` columns. Priority: `Shipping Phone` > `Phone` > `Billing Phone`; the others are listed as alternatives.
- A file where every date is like `05/06/2026` (ambiguous) forces the date-format choice.
- Payment values `COD` and `Paid` in one file: `Paid` rows are excluded after the merchant confirms the classification.
- The merchant changes the country after review. All phones are re-normalized from raw values.

## Implementation notes

- **Backend:** `column-matcher.ts` (pure function: headers + sample rows → suggestions) and `payment-value-classifier.ts`, both pure and fully unit tested. Validation of the mapping body uses class-validator DTOs. Re-validation runs in the request for up to 5,000 rows (target under 2 s); if it's slower, move it to the `order-import` queue with a `validating` flag and have the client poll.
- **Frontend:** Covered in US-04.6-05.
- **Data:** Profiles are merchant configuration and hold no customer data.
- **Operations:** Log which fields were auto-detected versus changed (field names only) to tune the dictionary.

## Test requirements

- Matcher table tests for every alias, Arabic normalization variant and the `name` ambiguity rule. Payment classifier tests. Mapping validation errors. Saved profile apply, partial apply and mismatch.
- Satisfy the applicable [shared Definition of Done](../README.md); record test results during implementation, not when this backlog is authored.

*Decisions and deviations.*
- The suggestion is stored on the draft at upload (`mapping.confirmed = false`), so a refreshed wizard can resume. `mappingDictionaryVersion` lives in `batch.mapping.dictionaryVersion` because the story rules out a migration.
- Blank payment cells are counted (`blankCount`) but need no merchant choice. What a missing method means stays with the store's `assumeCodWhenPaymentMissing` through `OrderEligibilityService` (US-04.6-04).
- Negated values (`غير مدفوع`, `unpaid`, `not paid`, `non cod`) classify as `unknown`, for the merchant to decide.
- `IMPORT_MAPPING_INCOMPLETE` also covers the data-dependent refusals, each with a field error:
  - an ambiguous date with `dateFormat: 'auto'`: `options.dateFormat`;
  - an unresolved payment value: `options.paymentValueMap`.

  The body carries `paymentValues` and `dateFormat`, so the UI can show choices for a column the merchant just selected.
- A header of only `#` has an empty key and matches nothing. `Phone (2)` is matched as `Phone` only when `Phone` exists.
- Choices sent for payment values that are not listed are dropped before storing. Keys are normalized with `normalizePaymentValue`.
- Operations log `order-import-mapping-save` records `detectedFields`/`savedFields`/`changedFields` (field names only) and `durationMs`.

*Known limitations.*
- No row validation until US-04.6-04: counts stay `{}`.
- No UI (US-04.6-05).
- Re-validation timing will be measured in US-04.6-04.
