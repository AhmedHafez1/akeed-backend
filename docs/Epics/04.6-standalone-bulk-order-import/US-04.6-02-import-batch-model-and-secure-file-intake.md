## User story and value

As a Standalone owner or admin, I want to upload the CSV or Excel file I already have, so that I don't have to reformat or re-save it before Akeed can read my orders.

**Business value:** This removes the main support burden of spreadsheet import (encoding, delimiter and Excel quirks) and creates the durable batch that every later step reads from.

## Scope

- The batch/row/profile schema.
- The multipart upload endpoint.
- Type, size and structure limits.
- Encoding and delimiter detection.
- CSV and XLSX parsing into a uniform grid.
- Header normalization.
- The file-hash warning.
- Persisting raw rows.
- Template downloads.
- The draft cap and discard.

**Out of scope:** Field mapping logic (US-04.6-03), validation (US-04.6-04), object storage and streaming uploads over 5 MB.

## Acceptance criteria

1. `POST /api/order-imports` accepts one multipart `file` field from an owner/admin of a Standalone org with completed onboarding and the flag on. Otherwise it returns `IMPORT_DISABLED`, `IMPORT_ROLE_REQUIRED`, `IMPORT_SOURCE_UNSUPPORTED` or `IMPORT_SETUP_INCOMPLETE`, before reading the body where possible.
   - The role, single-active-source, Standalone-only and onboarding checks are **extracted** from `OrdersService.createManualOrder` into `StandaloneSourceResolver.resolveWritable(user, codeMap)`. `createManualOrder` then calls it with its existing `MANUAL_ORDER_*` codes, with unchanged status codes and bodies.
   - The import calls the same resolver with the `IMPORT_*` code map. No other code in this epic re-derives the source.
2. Files over 5 MB are rejected by the upload limiter with `IMPORT_FILE_TOO_LARGE`, without buffering the whole body. A missing file returns `IMPORT_FILE_REQUIRED`.
3. The format is decided by content, not the extension or client MIME type:
   - ZIP magic with an `xl/workbook.xml` part is XLSX.
   - An OLE2/CFB header means legacy `.xls` or a password-protected XLSX. These return `IMPORT_FILE_TYPE_UNSUPPORTED` or `IMPORT_FILE_PROTECTED` respectively.
   - A workbook with `vbaProject.bin` (macros) is rejected.
   - Other binary content returns `IMPORT_FILE_UNREADABLE`.
   - Otherwise the file is text.
4. Text decoding order:
   1. The BOM (UTF-8, UTF-16 LE/BE).
   2. Strict UTF-8.
   3. Windows-1256.

   The detected encoding is stored. The delimiter is chosen among `,`, `;` and tab by the most consistent column count over the first 50 non-empty lines; a tie prefers `,`. RFC 4180 quoting is honored, including multi-line cells. A malformed quote produces a row-level parse issue on that row only.
5. XLSX reads the first **visible** worksheet. Cells use their cached value, and formulas are never evaluated. Dates become ISO strings. Numbers keep the displayed text where the cell has a text or custom format, so phone numbers are not reformatted. Merged ranges keep the value in their top-left cell only. The response lists ignored sheet names.
6. Zip-bomb and size guards: total uncompressed size over 50 MB, or more than 5,000 non-empty data rows, or more than 100 columns, aborts with `IMPORT_FILE_UNREADABLE`, `IMPORT_ROW_LIMIT_EXCEEDED` or `IMPORT_COLUMN_LIMIT_EXCEEDED`. Nothing is persisted for an aborted upload.
7. Header handling:
   - The first non-empty row is the header. Headers are trimmed and NFC-normalized.
   - Blank headers become `Column N`. Duplicates get ` (2)`, ` (3)` suffixes.
   - Fully blank data rows are dropped and not counted.
   - Cells are trimmed. Values over 1,000 characters are truncated and flagged `FIELD_TOO_LONG`.
   - Rows with more cells than headers keep the extras under `Column N`. Missing cells are empty.
   - A file with a header but no data rows returns `IMPORT_FILE_EMPTY`.
8. On success, one transaction creates `order_import_batches` in `draft` (expires in 24 h) and inserts all rows in chunks of 500 as `{rowNumber (1-based spreadsheet row), raw: {header: value}}`. It returns `{batchId, status, fileName, format, encoding, delimiter, sheetName, ignoredSheets, headers, rowCount, sampleRows (first 5), duplicateFileOf?}`.
9. If a batch with the same SHA-256 exists for the org in the last 24 h (any status except `expired`), the response includes `duplicateFileOf: {batchId, createdAt, status}`. The client shows a warning; this is not an error.
10. More than 3 open drafts returns `IMPORT_TOO_MANY_DRAFTS`, listing the drafts to resume or discard. `DELETE /api/order-imports/:id` discards a `draft` (rows purged). Any other status returns `IMPORT_BATCH_STATE_CONFLICT`.
11. `GET /api/order-imports/template?format=csv|xlsx&locale=ar|en` returns a sample file with headers `order_id, customer_name, phone, amount, currency, payment_method, order_date, city, address, notes` (Arabic header labels for `ar`) and two Egyptian example rows. The CSV is UTF-8 with BOM.
12. The file name is stored sanitized: path segments stripped, control and bidi-override characters removed, at most 150 characters. It is never used as a filesystem path.

## Data contract

```text
order_import_batches
  id uuid PK, org_id uuid FK, integration_id uuid FK, created_by uuid,
  status text CHECK IN ('draft','committing','awaiting_start','releasing','paused',
                        'completed','stopped','not_started','expired','failed'),
  file_name text, file_sha256 char(64), file_size int, file_format text ('csv'|'xlsx'),
  encoding text NULL, delimiter text NULL, sheet_name text NULL,
  headers jsonb, row_count int,
  mapping jsonb NULL, options jsonb NULL, mapping_profile_id uuid NULL,
  counts jsonb NOT NULL DEFAULT '{}',          -- ready/invalid/duplicate/excluded/imported/released/withdrawn
  order_date_min date NULL, order_date_max date NULL,
  commit_idempotency_key text NULL, start_idempotency_key text NULL,
  committed_at, attested_by uuid, attested_at, attestation_version text,
  started_at, paused_reason text NULL, completed_at, expires_at, start_deadline_at,
  short_code text NOT NULL,                     -- 6-char base32, for IMP-<code>-<row>
  created_at, updated_at
  UNIQUE (org_id, commit_idempotency_key), UNIQUE (org_id, short_code)
  INDEX (org_id, created_at DESC), INDEX (org_id, file_sha256, created_at)

order_import_rows
  id uuid PK, batch_id uuid FK ON DELETE CASCADE, org_id uuid,
  row_number int, raw jsonb, normalized jsonb NULL,
  outcome text NULL CHECK IN ('ready','invalid','duplicate','excluded','imported'),
  issues jsonb NOT NULL DEFAULT '[]',          -- [{code, field?, params?}]
  include_override boolean NOT NULL DEFAULT false,
  dedupe_key text NULL, collapsed_into int NULL,
  order_id uuid NULL, webhook_event_id uuid NULL
  UNIQUE (batch_id, row_number), INDEX (batch_id, outcome, row_number)

order_import_mapping_profiles
  id uuid PK, org_id uuid, header_signature char(64), mapping jsonb, options jsonb,
  updated_by uuid, updated_at
  UNIQUE (org_id, header_signature)
```

Row-level security matches `orders`: `org_id = get_user_org_id()`.

## Edge cases

- A `.csv` extension on an XLSX file is parsed as XLSX. A `.xlsx` extension on CSV text is parsed as CSV.
- UTF-16 LE tab-separated "Unicode text" saved by Arabic Excel parses to correct Arabic.
- A Windows-1256 CSV decodes Arabic correctly and records `encoding = windows-1256`.
- A hidden first sheet is skipped in favor of the first visible one.
- A sheet with formatting applied to 1,048,576 rows but data in 40 counts 40 rows.
- Phone cells formatted as numbers: if the stored value is numeric, the raw numeric string is kept and US-04.6-04 flags scientific notation or the missing leading zero.
- Excel serial dates, including the 1900 leap-year bug, convert to ISO dates.
- An interrupted upload leaves no batch.
- Two identical uploads 1 second apart: both succeed as separate drafts, and the second carries `duplicateFileOf`.

## Implementation notes

- **Backend:**
  - New `src/modules/order-imports/` module: controller, service, `parsers/{file-sniffer,text-decoder,csv-grid.parser,xlsx-grid.parser}.ts` producing `Grid = {headers: string[], rows: {rowNumber, cells: string[]}[]}`, and repository.
  - Use `FileInterceptor` with memory storage and `limits: {fileSize, files: 1, fields: 5}`. Parse with a streaming CSV parser. Choose an XLSX reader per the epic's dependency note, and enforce the uncompressed-size cap while inflating.
  - Run parsing off the request's event-loop hot path if a 5,000 × 100 file exceeds 1 s (worker thread acceptable).
  - `@Throttle` 10 per minute per user.
- **Frontend:** No UI in this story beyond typed API functions. `fetchWithAuth` must allow a caller to omit `Content-Type` for `FormData`, so the browser sets the multipart boundary.
- **Data:** Additive migration for the three tables. A daily purge job (US-04.6-09) deletes expired drafts.
- **Operations:** Log the batch ID, format, encoding, row count and duration. Never log cell values or the file name.

## Test requirements

- Fixture tests for each encoding, delimiter and XLSX quirk listed above. Tests for limit boundaries: exactly 5,000 rows, 5,001 rows, 100 and 101 columns, and a 5 MB + 1 byte file.
- Tests for protected, macro, legacy `.xls`, PDF-renamed and zip-bomb files; role, flag and Shopify denial; the draft cap; and discard.
- `StandaloneSourceResolver` unit tests for both code maps. The manual-order contract suite passes unchanged after the extraction.
- Satisfy the applicable [shared Definition of Done](../README.md); record test results during implementation, not when this backlog is authored.

## Migration and rollout

The migration is additive, and the endpoint is gated by `STANDALONE_BULK_IMPORT_ENABLED`. Rollback: disable the flag. The tables can remain.
