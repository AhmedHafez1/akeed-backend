## 3. Daily quality log (AC8)

Record the log every day from the first pilot import until **7 days after the last pilot release**. Record one row per day even when nothing changed.

| Date | Time checked | Phone-number quality rating (GREEN/YELLOW/RED) | Messaging limit tier | Template: name → status (APPROVED/PAUSED/DISABLED, quality) | Imported sends that day | Manual sends that day | Block/report signals: imported | Block/report signals: manual | Notes | Checked by |
| ---- | ------------ | ---------------------------------------------- | -------------------- | ----------------------------------------------------------- | ----------------------- | --------------------- | ------------------------------ | ---------------------------- | ----- | ---------- |
|      |              |                                                |                      |                                                             |                         |                       |                                |                              |       |            |

How to fill the columns:

- **Sends per day by source:** `message_dispatches` joined to orders, where `orders.raw_payload->>'ingestionType'` is `bulk_import` or `manual`. Record counts only.
- **Block/report signals:** whatever Meta exposes for the number (quality-rating reasons, "customers blocked or reported" notices in WhatsApp Manager). Where Meta gives no per-message attribution, record the qualitative notice and the send mix for that day.

**Blocking rules (any one blocks general availability):**

1. The quality rating drops (GREEN → YELLOW, or YELLOW → RED) on any day in the window.
2. A template used for verification is PAUSED or DISABLED.
3. Block/report signals on imported orders exceed those on manual orders over the window, normalized per 1,000 sends.

A block stays in place until the cause is explained in the go/no-go record and the pacing (`BULK_IMPORT_RELEASE_PER_MINUTE`) or the policy is adjusted, and a new 7-day window then passes clean.

## 4. Rollback

Use these steps in order. Stop at the first one that is enough.

1. **One merchant:** remove that org's UUID from `BULK_IMPORT_PILOT_ORG_IDS` and restart. New uploads, mapping, commit, start and resume for that org answer `IMPORT_DISABLED`. Stop keeps working, and batches already releasing finish at the configured pace.
2. **Stop a releasing batch now:** as an owner or admin of that org, call `POST /api/order-imports/:id/stop` (it works even with the flag off). Unreleased orders are withdrawn (`not_started`), and nothing is billed for them.
3. **Everyone:** set `STANDALONE_BULK_IMPORT_ENABLED=false` and restart (the US-04.6-09 kill switch). The effect on every org is the same as step 1.
4. **Slow down instead of stopping:** lower `BULK_IMPORT_RELEASE_PER_MINUTE` (1–120, default 20) and restart. The next tick uses the new rate.
5. **Existing imported orders** keep their normal lifecycle in Verifications (confirm, cancel, no reply, retry). No data migration is needed for any rollback step.

Record every rollback in the go/no-go record with the date, reason and step used.

## 6. Adding a real merchant sample to the fixture pack

1. Get the file from the merchant with their permission.
2. Anonymize it before it leaves the secure machine:
   - replace every customer name with a synthetic name of the same script (Arabic/Latin) and a similar length;
   - replace every phone with a synthetic number of the same shape (same country, prefix style and formatting: spaces, dashes, `+`, `00`, Arabic-Indic digits, scientific notation);
   - replace addresses and cities with synthetic ones;
   - scale amounts by a random factor, keeping their format (separators, currency words);
   - replace order references with synthetic ones of the same pattern;
   - keep headers, column order, sheet structure, encoding, delimiter, formulas, merged cells and date formats **unchanged**. Those are what the fixture is for.
3. Add it to `scripts/order-import-fixtures/` as a checked-in anonymized source file, with a hand-written manifest (per-row outcome and issue codes), and regenerate with `npm run fixtures:order-imports`.
4. Record it in the go/no-go record under "real file shapes".
