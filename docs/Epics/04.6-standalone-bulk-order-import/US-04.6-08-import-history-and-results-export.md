## User story and value

As a merchant with no store integration, I want to download which of my imported orders were confirmed, canceled or unanswered in a file I can open in Excel, so that I can decide what to ship without copying results by hand.

**Business value:** This closes the loop. For merchants without an integration, the results file is the deliverable. Import history also gives support and merchants one place to answer "what happened to my file?".

## Scope

- The history list.
- Batch detail with live lifecycle counts.
- `results.csv` and `errors.csv` streaming exports with spreadsheet-safe encoding.
- Navigation entry points.
- A verifications filter by import.

**Out of scope:** Pushing results to external systems, scheduled exports, XLSX export, and editing orders.

## Acceptance criteria

1. The sidebar gains "Import orders / استيراد الطلبات" (Standalone only, flag on). It routes to `/imports`, which lists batches newest first (cursor, 20 per page).
   - Each row shows the file name, created time and actor, status badge, total rows, imported and not-imported counts, and confirmation progress (confirmed ÷ imported), with actions Open, Download results and Download errors.
   - The empty state explains the feature and has a "New import" button and template links.
   - The dashboard's Standalone empty state and the manual-order top-bar action gain a secondary "Import from file" entry.
2. `GET /api/order-imports/:id` includes:
   - Batch metadata and mapping summary.
   - Import counts by outcome and issue code.
   - Hold counts (awaiting_start, released, not_started).
   - Lifecycle counts for imported orders, from the same projection the dashboard uses: awaiting_start, accepted/processing, pending/sent/delivered/read, confirmed, canceled, no_reply, failed/blocked/review_required, not_started.
   - `startDeadlineAt`, `pausedReason` and the attestation actor and time.
3. `GET /api/order-imports/:id/results.csv` streams one line per source row (not only imported rows), ordered by row number. Columns (EN headers, or AR when `locale=ar`):
   - `row`, `order_reference`, `customer_name`, `phone`, `amount`, `currency`
   - `import_result` (imported / needs_fixing / duplicate / excluded)
   - `import_reason` (localized)
   - `confirmation_status` (localized lifecycle, or empty)
   - `status_updated_at` (store timezone, `YYYY-MM-DD HH:mm`)
   - `messages_sent`, `akeed_order_id`
4. `GET /api/order-imports/:id/errors.csv` streams the original file's columns, in original order with original headers, for every row whose outcome is invalid, duplicate or excluded, plus `akeed_row`, `akeed_status` and `akeed_reason`. The file can be edited and re-uploaded with the same mapping profile; the `akeed_*` columns are ignored on re-upload by the header matcher.
5. Every generated CSV:
   - is UTF-8 with BOM and CRLF line endings, quoted per RFC 4180;
   - prefixes any cell starting with `=`, `+`, `-`, `@`, tab or carriage return with `'`;
   - gets a sanitized `Content-Disposition` filename (`<original-base>-results-<yyyymmdd>.csv`, ASCII fallback plus RFC 5987 `filename*`);
   - is served with `Cache-Control: no-store`.

   Phones are written with the leading `+` preceded by `'` so Excel does not coerce them.
6. Exports are available to any member of the org at any status after upload. Drafts export errors only. After the 90-day row retention, results fall back to imported orders only (via `orders.raw_payload.importBatchId`), and the detail page says so.
7. The verifications page accepts `?importBatchId=` and shows a dismissible "From import: {file}" chip. The filter is org-scoped.
8. Exports for 5,000 rows stream in under 5 s, with constant memory (cursor-based, no full materialization).

## Edge cases

- A file name with Arabic, spaces, quotes or RTL override characters (sanitized).
- A cell value `=HYPERLINK("http://x")` in the source (escaped in both exports).
- Names starting with `-` or `+` (escaped; the leading `'` is visible in Excel only in the formula bar).
- A batch with 0 imported rows (results still list all rows).
- An export requested while releasing (a snapshot at request time).
- A viewer downloading (allowed).
- Another org's batch ID (404).
- The export after row purge (reduced columns, with a banner).
- A very long original header set of 100 columns (preserved in errors.csv).

## Implementation notes

- **Backend:**
  - A `csv-writer.util.ts` with a single `escapeCell` implementation plus the BOM, shared by both exports and the template download.
  - Stream with a Postgres cursor or keyset pagination through a Node `Readable`.
  - Lifecycle via the existing `retryGuardStatus` expression joined by `order_id`. Don't copy the CASE; export it from `orders.repository.ts` for reuse.
- **Frontend:**
  - `/imports` page and batch detail.
  - Download via an authenticated fetch that turns the response into a Blob; the token is never put in a query string. Promote `features/billing/lib/csvDownload.ts` to `src/shared/lib/download.ts` with `downloadBlob(blob, filename)`, keeping `downloadCsv` as a thin wrapper, and use it here. Don't add a second anchor/object-URL helper.
  - Reuse `Table`, `Pagination`, `Badge`, and the stacked bar built from tokens (no new chart library).
- **Data:** No new tables.
- **Operations:** Log export requests (batch ID, type, row count), without PII.
