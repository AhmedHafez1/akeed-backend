# US-04.5-09 — Standalone signup auto-activation

Date: 2026-09-13

Story: [US-04.5-09](Epics/04.5-standalone-paymob-usage-billing/US-04.5-09-standalone-signup-auto-activation.md)

Supersedes: [US-04.5-02 approval and one-time grant](US-04.5-02-APPROVAL-AND-ONE-TIME-GRANT-EVIDENCE.md)

## Flow

Before: signup → email verification → staff approval → account active → 30 free credits.

After: signup → email verification → account active → 30 free credits.

Supabase issues no session until the email address is confirmed, and `POST /api/organizations` (Standalone provisioning) requires a Supabase session. The grant therefore follows verification without any new backend check. The Supabase project's **Confirm email** setting must stay enabled; this story does not change the verification flow.

## Delivered boundary

Backend:

- `ensureActiveCreditAccount` (credit accounting repository) inserts the account `active` with `posted_balance = freeGrant` and, only when that insert wins, the `free_grant` ledger entry (`actor_id` = owner, reason `signup_auto_activation`, key `standalone-free-grant:<orgId>:v1`). Provisioning calls it inside its advisory-locked transaction, in both credit-billing modes.
- `CreditApprovalService` became `CreditEligibilityService` (`readStatus`, `resolveDenial`). `STANDALONE_APPROVAL_REQUIRED` is no longer emitted; a missing account reports `CREDIT_ACCOUNT_NOT_PROVISIONED`. The legacy codes stay in the reopenable/blocked lifecycle lists so rows blocked before this change can resume.
- Onboarding reports `standaloneSetup.accountStatus` and blocks only `account_suspended`.
- Removed: `POST approvals/preview`, `POST approvals/apply`, `StandaloneBillingPolicy`, preview/apply repository code, `STANDALONE_CREDIT_APPROVAL_ENABLED`, `BILLING_ACCOUNT_NOT_APPROVED`. The account list now returns plain account rows. Account detail reports `activatedAt` from the grant's ledger time. Observability reports `activatedOrganizations` and dates first-send latency from the grant.
- Migration `0035_standalone_auto_activation.sql`.

Frontend:

- Onboarding waiting-for-approval screen removed; a suspended-account screen remains.
- Staff account list without selection, preview, reason, apply or report download.
- Denial feedback, billing notice, manual-order errors and the smoke fixtures use the new vocabulary.
- Landing, pricing, how-it-works and FAQ copy (Arabic and English) describe instant activation. JSON-LD availability is `InStock`.

Shopify: no Shopify code path changed. `usesPrepaidCredits` is still `platformType === 'standalone'`, and provisioning still refuses users owning any native source.

## Migration preflight

Run read-only before deploying `0035`. Any row returned makes the migration abort; escalate those organizations instead of editing data.

```sql
SELECT account.org_id
FROM credit_accounts account
WHERE account.status::text = 'pending_approval'
  AND (
    EXISTS (SELECT 1 FROM integrations source WHERE source.org_id = account.org_id AND source.platform_type <> 'standalone')
    OR EXISTS (SELECT 1 FROM billing_free_plan_claims claim WHERE claim.org_id = account.org_id AND claim.platform_type <> 'standalone')
    OR (SELECT count(*) FROM memberships member WHERE member.org_id = account.org_id AND member.role = 'owner') <> 1
  );
```

The backfill grant quantity is the 30-credit default. Deployments that set a different `STANDALONE_FREE_GRANT` must adjust `0035` before running it.

Rollback: `0035` is forward-only. It drops the approval columns and enum value, and committed grants are immutable. Recover forward; never delete grants.

The `standalone-provisioning` contract replays `0035` against the pre-migration credit shape:

- A co-owned pending organization aborts the migration, naming it, with nothing changed.
- Once that is resolved, a pending organization gets `free_grant +30` from its owner, and an already-granted pending organization is only activated.
- The enum is `{active,suspended}`, and the approval columns are gone.
- Concurrent signup opens one active account with exactly one grant, and a later sign-in adds nothing.
- A Shopify owner is refused, and no credit account is opened.
